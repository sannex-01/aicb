## 2026-09-07 - Rate Limiting & Auth Password Policies
**Vulnerability:** The application was missing rate limits on sensitive authentication endpoints (`/login`, `/forgot-password`, `/reset-password`), making it susceptible to brute-force and enumeration attacks. Additionally, the password policy only required 6 characters without complexity requirements, allowing weak passwords.
**Learning:** In a FastAPI application using `slowapi`, rate limiting decorators (`@limiter.limit`) must be applied directly to the router endpoints. The front-end password strength validator must also be kept strictly in sync with the back-end API validation rules.
**Prevention:** Always implement rate limiting on authentication and sensitive endpoints. Ensure password policies enforce minimum length (e.g., 8 characters) and complexity (e.g., uppercase, lowercase, number). When updating validation rules on the backend, always audit and update the corresponding frontend validation logic (e.g., in `utils.js`) to prevent UX inconsistencies and unexpected server rejections. Always enforce password rules consistently across all user creation and modification endpoints (e.g., `create_user` and `update_user`).
